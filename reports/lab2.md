# Lab2：地址空间

## 1. 实验要求

本实验对应 rCore 第四章。第三章的内核把用户程序数据直接放在内核可以寻址的内存中，用户地址与内核地址没有区别，因此系统调用可以直接把用户传入的地址当作普通指针使用。第四章引入地址空间隔离：内核与每个用户程序各自拥有独立的页表，同一个数值地址在不同页表中对应不同的物理页，也可能根本没有映射。

隔离带来的直接后果是，第三章的实现方式全部失效。因此本章的目标是：让内核能够按照用户页表来访问用户内存，并让用户程序可以通过系统调用申请与释放内存。需要完成的系统调用如下。

| 系统调用 | 编号 | 目标 |
| --- | --- | --- |
| `sys_get_time` | `169` | 把时间写入用户提供的 `TimeVal`，需要处理结构体跨页的情况 |
| `sys_trace` | `410` | 在页表隔离下重新实现单字节读写，并保留系统调用次数查询 |
| `sys_mmap` | `222` | 在用户指定的虚拟地址处建立一段映射 |
| `sys_munmap` | `215` | 取消一段已有的映射 |

### 1.1 需要补充的内容

结合仓库在第四章的初始状态，本次实现增加了以下内容：

1. 在内核中提供按用户页表访问用户内存的能力，替换掉直接解引用用户指针的写法。
2. 完成 `sys_get_time` 的地址校验与跨页写回。
3. 按页表隔离的要求重写 `sys_trace` 的读写分支，并重建随任务保存的系统调用计数。
4. 为 `sys_mmap` 补齐参数校验、重叠检查与权限拼装。
5. 为 `MemorySet` 增加取消映射的接口，并在此基础上完成 `sys_munmap`。

仓库此时已经具备按 ELF 建立用户地址空间的代码（`MemorySet::from_elf`）、三级页表的查找与建立能力（`PageTable`）以及物理页帧分配器。本章的工作集中在系统调用层、任务层与内存层的接口衔接上，不修改页表本身的结构。

## 2. 方案设计

### 2.1 由 token 取得用户页表，不切换 satp

内核在系统调用期间使用的页表是内核页表，直接执行 `*ptr` 会按内核的映射解释用户地址。让内核临时切到用户页表需要保存现场并刷新 TLB，代价高且容易出错。

本次实现沿用仓库既有的方式：通过 `current_user_token()` 取得当前任务的页表 token，再用 `PageTable::from_token(token)` 构造一个只用于查表的对象，最后由 `translate()` 得到目标虚拟页对应的页表项。这个对象只解析 token 里的根页表物理页号，不拥有任何页帧，析构时不会影响原页表。

内核之所以能够直接访问查出的物理页，是因为内核地址空间对物理内存做了恒等映射。也就是说，翻译由内核软件完成，物理内存的读写仍走内核自己的映射。

### 2.2 预检查与提交分开

用户传入的地址完全不可信。本次实现统一采用"先检查、后写入"的顺序：`sys_get_time` 先把目标区间覆盖的所有页检查一遍，确认存在且可写，再开始复制；`sys_trace` 先翻译再读写；`sys_mmap` 先把整个区间扫一遍确认没有冲突，再建立映射。

这样处理的效果是失败时不留半成品：检查阶段发现问题的调用直接返回 `-1`，不会出现"前半段已写入、后半段报错"的情况。

检查阶段有一个共同的陷阱：仓库的 `translate()` 沿页表走到末级后会原样返回该页表项，即使这一项无效，也返回 `Some`。因此判断依据必须是 `pte.is_valid()`，不能只看是否 `is_some()`。这一点在 `sys_get_time`、`sys_trace` 与 `sys_mmap` 中都成立。

### 2.3 映射的生命周期交给 MemorySet

`sys_mmap` 需要分配物理页，但页帧必须有人持有，否则分配的页会在持有者析构时被回收。仓库中承担这一职责的是 `MemorySet::insert_framed_area()`：它构造 `MapArea`，逐页调用 `frame_alloc()` 并把页帧存进自己的 `data_frames`，同时把区间记录到 `areas`。

因此 `sys_mmap` 不直接调用 `frame_alloc()` 或 `PageTable::map()`，而是走这个接口。这样页帧的生命周期与映射绑定，任务退出时随地址空间一起释放，后续实现取消映射时也有明确的处理对象。

同一个思路反过来要求 `sys_munmap` 必须补一个删除接口：`MemorySet` 原本只有插入没有删除，而清页表项与归还页帧都需要按区间来做，放在 `syscall` 层既拿不到 `areas`，也无法保证两件事同时完成。

### 2.4 分层与调用链

三个系统调用都遵循同一套三层结构：

```text
syscall 层（os/src/syscall/process.rs）
  只做参数语义与转发，不直接接触页表
task 层（os/src/task/mod.rs、os/src/task/task.rs）
  定位当前任务，承载与任务状态相关的校验与操作
mm 层（os/src/mm/memory_set.rs）
  完成页表修改与页帧管理
```

这样安排有两个原因。其一，改页表必须以"当前任务"为前提，而任务管理器 `TASK_MANAGER` 是 `task` 模块私有的静态变量，`syscall` 模块无法访问，只能由 `task` 模块提供入口。其二，`exclusive_access()` 返回的借用只在当前函数内有效，把构造 `MemorySet` 的逻辑留在持有借用的函数里，避免出现绕过借用检查的 `&'static mut` 引用。

## 3. 文件修改与实现

### 3.1 `os/src/syscall/process.rs`：完成 `sys_get_time`

目标是把时间写入用户提供的 `TimeVal`。在 RV64 上该结构体是两个 `usize` 字段，共 16 字节，起始地址不保证落在页边界内，因此一次整体写入并不可靠：相邻的两个虚拟页映射到的物理页不一定相邻。

实现按四步组织：

1. 用 `start.checked_add(len)` 计算区间末尾，同时挡住加法溢出。
2. 拒绝空地址与超出 Sv39 低半区的区间。这一步必须对原始数值地址做，因为 `VirtAddr::from()` 会截取低 39 位，先检查可以避免高位被截断后误判为合法地址。
3. 逐页检查页表项，要求 `V | U | W` 同时成立。按页步进而不是逐字节查询，步长取"当前页剩余字节"与"区间剩余字节"的较小值。
4. 读取时钟并编码为 16 字节，再通过 `translated_byte_buffer()` 取得目标页的物理内存切片，逐段复制。

第 4 步用字节数组而不是从用户指针构造 `&mut TimeVal`，好处是复制边界由页决定，字段可以被拆到两页中写入，也不要求用户地址满足结构体对齐条件。

### 3.2 `os/src/syscall/process.rs`：重写 `sys_trace`

第三章的 `sys_trace` 把 `id` 转成裸指针后直接解引用。在地址空间隔离之后，这个写法会按内核页表解释用户地址，既可能访问到内核数据，也无法做权限检查。本章按请求类型分别处理：

- 请求 `2` 不涉及内存，优先处理：直接返回当前任务的计数，因为本次调用在分发时已经计数。
- 请求 `0` 与 `1` 先把 `id` 当作虚拟地址，用 `translate()` 取得页表项，要求 `V | U` 成立；读取还需 `R`，写入还需 `W`。检查通过后，通过页表项的物理页号取得该页字节数组，按页内偏移读写那一个字节。

这样处理后，尚未映射的地址、内核地址、以及被取消映射的地址都会返回 `-1`，只读页上的写入也会被拒绝，而不是把异常留给硬件。

### 3.3 `os/src/task/task.rs` 与 `os/src/task/mod.rs`：重建计数与映射操作

系统调用计数需要随任务保存，因此计数数组作为 `TaskControlBlock` 的字段，其长度使用配置中的 `MAX_SYSCALL_NUM`：

```rust
pub syscall_times: [u32; MAX_SYSCALL_NUM],
```

数组在任务创建时清零，`add_syscall_count()` 与 `syscall_count()` 两个方法都带下标检查：超出范围的编号在更新时跳过、查询时返回 `0`。这样做的目的是不让统计逻辑成为新的崩溃点——不支持的系统调用编号仍由原有的分发分支报错。

`TaskControlBlock` 上另加两个方法承载映射操作。`mmap()` 依次完成参数校验、区间取整、重叠检查与权限拼装：

```rust
if start % page_size != 0 || len == 0 || port == 0 || port & !0b111 != 0 {
    return -1;
}
```

- 起始地址必须页对齐，长度不必，末尾向上取整到页边界。
- `port` 的第 0 位映射到 `R`、第 1 位映射到 `W`、第 2 位映射到 `X`，并且必须无条件带上 `U`，否则映射在用户态不可访问。
- 重叠检查逐页调用 `translate()` 并用 `is_valid()` 判断。这一步必须放在插入之前：`PageTable::map()` 内部有"同一页不得重复映射"的断言，直接插入会让内核 panic，而测例要求返回 `-1`。

`munmap()` 校验起始地址对齐、长度非零，把长度向上取整为页数后交给内存层。

`task/mod.rs` 在 `TaskManager` 上增加对应方法，用 `inner.current_task` 定位当前任务后转发，并在模块级暴露 `add_syscall_count()`、`syscall_count()`、`mmap_current_task()` 和 `munmap_current_task()` 四个入口。

### 3.4 `os/src/syscall/mod.rs`：统一入口计数

在分发的 `match` 之前插入一行：

```rust
crate::task::add_syscall_count(syscall_id);
```

顺序放在分发之前有两个作用：`sys_trace` 查询时能够看到包含本次调用的统计结果；`sys_yield` 与 `sys_exit` 在切换或结束任务之前完成计数，调用归属保持正确。

### 3.5 `os/src/mm/memory_set.rs`：新增取消映射接口

新增的方法按起始虚拟页号定位区间，核对页数后完成清理：

```rust
pub fn remove_area_with_start_vpn(&mut self, start_vpn: VirtPageNum, pages: usize) -> bool
```

清理动作包含两件事，缺一不可：

- `MapArea::unmap()` 逐页清空页表项，同时把 `FrameTracker` 从 `data_frames` 中移出。`FrameTracker` 析构即调用 `frame_dealloc()`，物理页回到分配器，不需要额外的释放调用。
- `areas.remove(idx)` 把区间记录移除，使区间表与页表保持一致。

页数核对放在所有修改之前，不通过就直接返回 `false`，因此失败时不会有任何副作用。要求页数精确匹配是被测例固定的：`munmap(start, len + 1)` 在这种情况下必须返回 `-1`，而不是释放一部分。

## 6. 遗留问题

- 用户地址范围校验不完整。`sys_mmap` 只检查页对齐与重叠，没有限制映射地址必须落在用户程序预留的区间内；`VirtAddr::from()` 会截取低 39 位，若用户传入高位非零的地址，重叠检查会落到另一个页上。`sys_get_time` 因为额外做了低半区检查，不受这一影响。
- `munmap` 只支持整段释放。区间必须与某个已有映射的起始页号和页数都一致，不支持释放大区间的一部分。
- 映射不是按需分配。`mmap` 调用时立即分配并映射全部物理页，没有惰性分配，也没有文件映射与写时复制。
- 统计范围固定。计数数组长度取 `MAX_SYSCALL_NUM`，超出该范围的编号不计数，新增系统调用时需要同步确认这个上限。
- 并发保护依赖单核环境。地址空间与任务状态的访问都靠 `exclusive_access()` 保证互斥，这是单核假设下的做法。

## 7. 实验总结

第四章的改动集中在"内核如何按照用户页表访问用户内存"这一条主线上。`sys_get_time` 与 `sys_trace` 把直接解引用改为按 token 翻译后访问物理页，`sys_mmap` 与 `sys_munmap` 把地址空间的管理职责交给 `MemorySet`，系统调用层只保留参数语义与转发。

三个共同点贯穿本章的实现：第一，判断映射是否有效必须看 `is_valid()`，因为 `translate()` 对无效项同样返回 `Some`；第二，检查和修改要分开，且检查要覆盖整个区间，失败时不留部分生效的状态；第三，页帧的申请与释放都通过 `MapArea` 完成，系统调用本身不直接管理物理页，这也是任务退出时能够自动回收地址空间的前提。

与第三章相比，本章的调试重点从系统调用本身的逻辑，转移到了内核与用户两个地址空间之间的边界上：哪些地址可以直接用、哪些必须翻译、翻译之后还需要检查什么，是本章的主要工作。
